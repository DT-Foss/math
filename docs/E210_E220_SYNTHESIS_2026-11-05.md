# E210–E220 synthesis — 2026-11-05

## 1. Direct hardware result

The completed continuation pushes the direct resident-V100 comparison into a new regime:

- local nonlinear residual graph: up to 235.17× CPU delta over V100 full at 8192²;
- composed Gram + 16-RHS Solve + Logdet: up to 225.93× at 8,388,608 rows;
- fused moments + Gram: 1152.60× at 33,554,432×64 FP64 with 64 changed rows;
- the supplied one-row generic path reaches 1627.18×.

The direct V100 baseline uses resident data; the CPU advantage is produced by state-transition algebra rather than transfer accounting.

## 2. The 1000× point is a state-complexity result

At n=33,554,432,d=64:

- full input is 16 GiB;
- sufficient statistics S,Q,G are 33 KiB.

The CPU update touches an amount of information determined by the changed rows and d, while the GPU full path still scans the entire n×d state.

The ratio therefore grows asymptotically with n for fixed edit complexity.

## 3. Midpoint/difference replacement is the canonical row-edit algebra

For D=new-old and P=new+old:

`Delta S = sum D`

`Delta Q = sum(D*P)`

`Delta G = 1/2(D^T P + P^T D)`.

Consequences:

1. one Gram GEMM instead of two;
2. no signed old/new stack;
3. direct small-delta arithmetic avoids subtracting two large quadratic forms;
4. the Gram update has a natural symmetric low-rank factorization.

## 4. Intrinsic delta rank can dominate edit count

If D=A B^T has rank r:

`C=A^T P`

`Delta G=1/2(B C + C^T B^T)`

and therefore

`rank(Delta G)<=2r`

regardless of how many rows were changed.

For coherent edits, the correct complexity variable is r, not e.

If the source already provides A,B, even D and new rows can be skipped:

`C = 2 A^T old + (A^T A) B^T`.

This is delta-native execution: preserve structure at the source instead of materializing it and rediscovering it later.

## 5. Change × Demand intersection is the general graph law

For dependency graph G, changed nodes U and requested outputs K, the raw nodes that can both be changed and matter to the request are:

`R = Desc(U) intersect Anc(K)`.

Every algebraic rewrite then contracts pieces of R further.

This unifies:

- spatial dirty cones;
- requested attention queries;
- sparse Fourier outputs;
- selected low-rank matrix blocks;
- incremental reverse-mode / gradient demand.

The 2-D local specialization computes forward dirty geometry and backward demand geometry at every layer and intersects them.

## 6. Sufficient state can be cold-backed

If future consumers depend only on S,Q,G / solver state, raw rows need not remain hot.

A 64-row update of the 32M×64 FP64 workload requires only 32 KiB of old rows. Even a relatively slow cold store can feed this small delta while the hot CPU state remains cache-sized.

This makes the runtime architecture:

`cold immutable base + sparse overlay + tiny sufficient hot state`.

## 7. Cache hierarchy becomes a routing coordinate

At d=64:

- dense FP64 Gram = 32 KiB;
- S+Q adds 1 KiB.

The complete sufficient state is therefore ~33 KiB and can live near core caches. This explains why software dispatch dominates the observed CPU delta time.

The runtime should dispatch by both edit structure and state footprint:

- rank-1 in-place native outer update;
- small-e specialized outer updates;
- midpoint GEMM for medium e;
- low-rank coherent update when factor provenance exists;
- GPU-delta for larger structured updates;
- GPU-full after the structured route crosses over.

## 8. Native persistent state, not delta-return APIs

A dynamic executor should update persistent S,Q,G in place.

Returning a dense Delta G, allocating temporaries, and adding it afterward is avoidable overhead.

The David Tom Foss native rank-1 reference demonstrates the intended interface: pre-bound state pointers and one state-transition call.

## 9. Covariance inherits low-rank structure

For fixed n:

`C=G/n-mu mu^T`

`Delta C=Delta G/n - mu dmu^T - dmu mu^T - dmu dmu^T`.

Thus if rank(Delta G)<=k:

`rank(Delta C)<=k+2`.

The dynamic PCA/eigensystem problem therefore already receives a low-rank covariance update; the missing piece is the eigensystem consumer, not the statistics producer.

## 10. New frontier: CPU-delta / GPU-delta / GPU-full

The direct 1000× result compares the correct CPU structured algorithm to a GPU full algorithm. The natural next phase diagram is:

`CPU_delta <-> GPU_delta <-> GPU_full`.

The calculus stays unchanged; only executor cost changes.

The likely regimes are:

- tiny state/cache-resident deltas: CPU;
- medium structured deltas: GPU-delta;
- high update density / dense requested output: GPU-full.

## 11. New frontier: incremental training and reverse demand

The change-demand intersection applies to reverse computation as well.

For an additive/local loss, sparse forward activation changes produce a bounded changed loss/adjoint region. Parameter gradients are themselves reductions of local activation/adjoint products, so old dirty contributions can be removed and new dirty contributions added.

This suggests an exact delta-autograd path:

`input/parameter edit -> forward dirty cone -> requested loss cone -> reverse dirty cone -> incremental gradient statistics`.

## 12. New frontier: branching state

Most replacement deltas are composable and often invertible.

A base sufficient state can therefore support many counterfactual branches without copying the underlying large state. Each branch stores only its delta ledger / factor state.

This is directly relevant to scenario analysis, optimization, simulation, search and speculative workloads.
