# Delta LSM — persistent state as base + compactable change layers

Wirkung's stateful operators share one systems pattern:

`stable base + cheap delta log/ledger + query merge + structure-specific compaction`.

This is analogous to an LSM tree, but the compaction algebra depends on mathematical structure.

## Delta memtables

| state | cheap delta form | compaction |
|---|---|---|
| row values | first-old / latest-new replacements | last-write-wins coalescing |
| additive statistics | Delta S / Delta Q / Delta G | addition |
| low-rank matrix | factor ledger | QR/SVD rank reveal |
| normalized weighted sum | K/V edit batches + row versions | coalesce edits; rebuild stale row on demand |
| dirty local graph | support components / tiles | geometry-aware merge |
| Fourier state | sparse point-value edits | sum/cancel edits at identical indices |
| solver | Woodbury factor/core ledger | block-Schur growth, then fold into factor state |
| cold-backed base | sparse hot overlay | page/crop fetch + eventual rewrite |

## Query cost versus compaction cost

A delta state is retained while:

`query_with_delta + expected_future_updates < compact/rebase + query_on_new_base`.

The threshold depends on:

- accumulated rank;
- support area/component count;
- edit-log length;
- requested-output width;
- query/update ratio;
- memory pressure;
- hardware executor costs.

## Matrix LSM

For matrix state:

`A_current = A_base + U V^T`.

Small rank:
- retain U,V;
- solve/logdet through Woodbury core.

Growing rank / many future queries:
- compact U,V by rank reveal;
- optionally fold the compact update into a Cholesky/QR/base factor;
- reset the delta ledger.

Full refactorization is only the final compaction route.

## Normalized-state LSM

K/V changes append to a versioned log.

Requested query rows reconcile only the suffix they have not seen. If the log is truncated, rows older than the retained suffix are invalidated and rebuilt exactly when next requested.

No global eager maintenance is required.

## Branching / snapshots

Because bases are immutable during a delta epoch, multiple branches can share one base and maintain independent compact delta ledgers. This makes counterfactual states, speculative evaluation and rollback possible without copying full state.

## Compiler consequence

The planner chooses both:
1. an execution representation;
2. a compaction schedule.

This turns rebase from an error-recovery mechanism into an ordinary costed state transition.
